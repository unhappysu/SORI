## 발표 정보

- 과제: SoundPLAN 실습을 토대로 한 앱 제작 기획안 발표(Claude·ChatGPT 활용 준비)
- 발표자: 전현수(서울시립대학교 환경공학부), 발표일 2026-11-12
- 발표 시간: **[__]분** (비어 있으면 10분, 질문 시간 제외)
- 청중: 담당 교수님과 수강생(SoundPLAN 실습 경험 있음)
- 앱 이름: SORI = Simulation of Outdoor Road-noise Impact, 우리말 '소리'

## 작성 기준

1. **슬라이드 순서 그대로** 13장 모두 씁니다. 장마다 `## N장 — 제목 (목표 시간)` 머리 아래에 실제로 소리 내어 읽을 문장만 씁니다.
2. 말투는 수업 발표용 존댓말(~습니다/~입니다), 한 문장은 짧게. 슬라이드 글을 그대로 읽지 말고 핵심을 풀어 말합니다.
3. 시간: 1분에 약 300자(공백 포함)를 기준으로 분량을 맞추고, 장마다 목표 시간을 적습니다. 피드백 문서의 시간 배분(10분 기준 약 9분 20초)을 출발점으로, 검증 현황(10장)에 가장 많은 시간을 줍니다.
4. 다음을 **반드시 지켜 주세요**(피드백 핵심).
   - SoundPLAN 을 깎아내리지 않습니다. SORI 는 대체가 아니라 국내 자료 연계와 계산 투명성에 초점을 둔 보완 도구입니다.
   - 검증은 세 가지를 구분합니다: 자동 시험 327개 = **구현 검증**(현장 정확도와 별개) / 현장 측정 = 모델이 약 **+5.7 dB** 높음, **원인 분석 중(미확정)** / SoundPLAN = 같은 수음점 2곳 **+0.30 / −0.01 dB**, 단 노면·반사 차수는 **SoundPLAN 기본값 가정**의 1차 비교이며 주변 도로 범위 차이로 격자 전체가 일치하지는 않음.
   - "+0.30 / −0.01 dB" 는 현장 측정값이 아니라 SORI 와 SoundPLAN **계산값끼리의 차이**라고 말로 분명히 합니다.
   - RLS-19 음원 + ISO 9613-2 전파 조합은 **SORI 의 구현 선택**이며 표준이 규정한 단일 모델이 아니라고 말합니다.
   - Windows 는 "실제 PC 점검 예정", macOS 는 "실행 확인"으로 말합니다.
   - AI 활용: Claude 로 표준식 구현·코드·자동 시험·문서화를 했고, 모델링 가정과 최종 판단은 사람이 했다는 점.
5. **파일에 없는 수치나 사실을 만들지 마세요.** 수치는 슬라이드·피드백 문서·요약 PDF 에 있는 것만 씁니다. 확인이 필요하면 `[확인 필요: …]` 로 표시합니다.
6. 장 전환 문장(다음 장으로 넘어가는 한 문장)을 각 장 끝에 넣습니다.
7. 13장 끝에는 30–40초 시연 순서(앱 실행 → 가상 교차로 예제 → 계산 실행 → 건물 클릭 → 3D 파사드)를 말로 안내하는 대본과, 시연이 안 될 때 쓸 대체 멘트(녹화 영상)를 넣습니다.

## 출력 형식

1. **전체 대본**: 장별 머리 + 대본 + (목표 시간, 대략 글자 수)
2. **시간 합계표**: 장 / 목표 시간 / 글자 수
3. **예상 질문 8개와 30초 안의 답변 대본**(피드백 문서의 Q1–Q8 기준, 같은 원칙 적용)
4. **발표 직전 확인 5가지**(말실수하기 쉬운 표현, 강조할 숫자)
