## 5. 발생한 오류와 원인

| 오류 | 원인 | 조치 |
|---|---|---|
| 앱에서 `Symbol not found: _proj_context_create` | pyproj·rasterio 휠이 같은 이름 `libproj.25.9.8.1.dylib` 를 넣는데 rasterio 판은 심볼이 `internal_proj_*`. PyInstaller 가 최상위에 rasterio 판 하나만 연결 | `packaging/macos_fix_dylibs.py`: 패키지별 자기 사본을 `@loader_path` 로 가리키게 고치고 재서명(겹치는 이름 9개, 72개 파일). macOS 휠(delocate)만의 문제 |
| `install_name_tool -id` 실패(libgif 등) | dylib 헤더 여유 공간 부족 | id 변경은 가능할 때만, 경로 변경만으로 동작 확인 |
| 앱에서 `No module named 'rasterio.serde'` | Cython 모듈 안의 import 를 PyInstaller 가 탐지 못함 | rasterio·pyproj·pyogrio 하위 모듈 전체를 hiddenimports 에 |
| 앱 실행 뒤 서명 깨짐(`a sealed resource is missing`) | `sori/__init__.py` 가 numba 를 먼저 import → 나중에 정한 `NUMBA_CACHE_DIR` 무시 → 앱 안 `__pycache__` 에 캐시 기록 | `setup_numba_cache` 에서 `numba.core.config.reload_config()` |

| GUI 창 화면 캡처 실패 | 이 세션에 화면 기록 권한 없음 | 버튼 함수를 코드로 호출해 동작 확인으로 대체 |

## 6. 미해결 문제

1. Windows 는 CI 러너에서 화면 없이 실행만 확인. 실제 Windows 10/11 PC 에서 GUI·SmartScreen 절차는 미확인(고정 버전 휠은 모두 설치됨).
2. macOS 앱은 arm64 전용. Intel Mac 용은 따로 빌드해야 함(예: Intel 러너).
3. 서명·공증 없음 → 처음 실행 때 Gatekeeper 경고(README 0.1절 절차).
4. 앱 크기 552 MB(rasterio·pyogrio 의 GDAL 두 벌, scipy 등). 줄이려면 별도 검토 필요.
5. `sori/inputs.py:118` affine `*` 연산 PendingDeprecationWarning — 엔진 입력 코드라 이번 작업에서 손대지 않음. affine 이 이 연산을 없애면 DEM 읽기가 실패할 수 있음.
6. `sori/maps_hq.py:382` 빈 도형 UserWarning(기존부터 있던 것).
7. 웹 화면(`app.py`, Streamlit)은 패키징 대상이 아니며 결과를 여전히 저장소 안 `projects/` 에 저장.
8. `field_survey/tests` 는 `openpyxl` 이 필요하지만 requirements 에 없음(CI 는 `tests/` 만 실행).
9. dylib 후처리는 현재 PyInstaller·휠 구조에 기대므로, PyInstaller 나 pyproj·rasterio 버전을 올리면 앱 `--selfcheck` 로 다시 확인해야 함.
10. GitHub Actions 경고: actions/checkout@v4·setup-python@v5·upload-artifact@v4 가 Node.js 20 대상이라 Node.js 24 로 강제 실행됨 — 새 판으로 올릴 필요.
