|---|---|---|---|


## 3. 화면 틀 후보 비교

| 기준 | A. PySide6(Qt Widgets) 단일 프로세스 | B. 웹 프런트엔드 + 파이썬 백엔드(pywebview) | C. 현 Streamlit 확장 |
|---|---|---|---|
| 앱 크기 증가(추정) | +60~90 MB(QtCore·Gui·Widgets 만, WebEngine 제외). 현재 552 MB 대비 약 +15 % | +10~20 MB(macOS WKWebView·pyobjc, Windows WebView2·pythonnet) + JS 라이브러리 수 MB | +80~120 MB(streamlit·tornado·pyarrow 등) + 브라우저 실행 필요 |
| PyInstaller 호환 | 공식 훅 있음(hooks-contrib), 사례 많음. `.app` 서명·플러그인 경로 검증된 조합 | 훅 있음. Windows 는 WebView2 런타임(Win10 일부는 별도 설치) 의존 | 서버 기동·포트·브라우저 열기 래퍼 필요. 정적 파일 수집 까다로움 |
| macOS·Windows | 같은 코드로 둘 다 네이티브 | 둘 다 가능하나 웹뷰 엔진이 OS마다 다름(Safari 계열 / Chromium 계열) | 브라우저 의존. 데스크톱 창이 아님 |
| 라이선스 | LGPLv3 — onedir 로 Qt 라이브러리를 바꿔 끼울 수 있게 두고 고지문 포함하면 됨 | BSD(pywebview), Leaflet BSD-2, OpenLayers BSD-2 | Apache 2.0 |
| 지도 표시 | matplotlib `QtAgg` 캔버스에 EPSG 5186 그대로 그림(좌표 왜곡 없음). 배경지도는 XYZ 타일을 받아 `rasterio.warp` 로 5186 재투영해 깔기(2단계). 큰 지도는 `QGraphicsView` 로 전환 가능 | Leaflet/OpenLayers + proj4 로 5186 정의, 배경지도 가장 쉬움. 결과는 GeoTIFF→PNG 겹치기 | folium(웹 메르카토르) — 지금처럼 "좌표 근사" 겹쳐보기 |
| 트리·속성 표·도킹 | 기본 부품(`QTreeView`, `QTableView`, `QDockWidget`) | 직접 만들거나 JS 라이브러리 필요 | 사실상 불가(마법사형) |
| 긴 계산 | `QThread` + 신호로 진행 표시, 중단 처리 쉬움 | JS↔파이썬 다리(`evaluate_js`)로 전달 | 스크립트 재실행 모델과 충돌 |
| 개발 언어 | 파이썬 하나 | 파이썬 + JS/HTML/CSS | 파이썬 하나 |
| 유지 비용 | 중간 | 높음(두 언어, 웹뷰 차이) | 낮지만 목표(SoundPLAN 수준) 도달 불가 |

**추천: A. PySide6(Qt Widgets) 단일 프로세스.**
- 프로젝트 트리·속성 표·도킹 창·긴 계산 관리가 기본 부품으로 되고, 파이썬 하나로 계산 엔진과 같은 프로세스에서 결과 배열을 바로 그림.
- 지도는 EPSG 5186 평면 좌표 그대로 그려 Streamlit 의 "좌표 근사" 문제가 없음. 배경지도만 B보다 손이 더 감(2단계에서 타일 재투영).
- 크기 증가는 WebEngine 을 빼면 GDAL 두 벌 대비 작음. LGPL 고지는 `packaging/` 에 라이선스 파일 추가로 처리.
- 기존 `sori_gui.py` 의 `run_job`·`selfcheck`·`--run`·`--selfcheck` 는 그대로 두고 화면 클래스만 Qt 로 새로 만듦. Qt 를 못 불러오면 기존 tkinter 화면으로 되돌아감(대체 경로).
- Streamlit 웹 화면(`app.py`)은 지우지 않고 웹용으로 유지함.
